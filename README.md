# Домашнє завдання до практичної №1 (варіант 4)

Дані варіанта: N = 37, F = 0.2.

## 1. Похибка представлення дробу F = 0.2

### Двійкове представлення (6 розрядів)

Множимо дробову частину на 2:

| Крок | Добуток | Цифра |
|------|---------|-------|
| 1 | 0.2 · 2 = 0.4 | 0 |
| 2 | 0.4 · 2 = 0.8 | 0 |
| 3 | 0.8 · 2 = 1.6 | 1 |
| 4 | 0.6 · 2 = 1.2 | 1 |
| 5 | 0.2 · 2 = 0.4 | 0 |
| 6 | 0.4 · 2 = 0.8 | 0 |

Отже, 0.2 ≈ 0.001100₂. Перевіряємо, яке число це насправді:

0.001100₂ = 2⁻³ + 2⁻⁴ = 0.125 + 0.0625 = **0.1875**

- Абсолютна похибка: |0.2 − 0.1875| = **0.0125**
- Відносна похибка: 0.0125 / 0.2 = **6.25 %**

### Округлення до 8 значущих десяткових цифр

0.2 = 0.20000000 (8 значущих цифр). Число 0.2 у десятковій системі скінченне, тому:

- Абсолютна похибка: **0**.
- Навіть для довільного числа порядку 0.2 округлення до 8 значущих цифр дає похибку не більше 5·10⁻⁹.

### Порівняння

| Спосіб | Значення | Абсолютна похибка |
|--------|----------|-------------------|
| 6 двійкових розрядів | 0.1875 | 0.0125 |
| 8 значущих десяткових цифр | 0.20000000 | 0 (максимум 5·10⁻⁹) |

Двійкове представлення з 6 розрядами гірше приблизно в **2,5 мільйона разів** за граничну похибку десяткового округлення (0.0125 / 5·10⁻⁹). Частково це різниця в кількості розрядів: 6 біт дають точність лише до 2⁻⁶ ≈ 0.0156. Але головна проблема глибша (див. нижче): скільки б розрядів ми не взяли, точно 0.2 у двійковій системі не записати.

### Чому похибка виникає навіть для «простих» дробів (0.1, 0.2, 0.3)

Дріб має скінченний запис у системі з основою q лише тоді, коли після скорочення його знаменник розкладається на прості дільники основи q.

- Десяткова система: основа 10 = 2 · 5, тому скінченні дроби з знаменниками виду 2ᵃ·5ᵇ. Для людини 0.2 = 1/5 «просте».
- Двійкова система: основа 2, тому скінченні лише дроби зі знаменником 2ᵏ (1/2, 1/4, 3/8 ...).

Розглянемо наші числа:

- 0.2 = 1/5, знаменник містить множник 5, якого немає в основі 2.
- 0.1 = 1/10 = 1/(2·5), той самий множник 5.
- 0.3 = 3/10, той самий множник 5.

Тому в двійковій системі вони нескінченні періодичні: 0.2 = 0.**0011** 0011 0011...₂ (період 0011). Комп'ютер має скінченну кількість розрядів (23 біти мантиси для single, 52 для double), тож обрізає цей ряд і зберігає наближене значення. Простота дробу в десятковій системі не означає простоти в двійковій, а похибка залежить від співвідношення знаменника й основи системи, а не від «довжини» числа. Саме тому 0.1 + 0.2 ≠ 0.3.

## 2. Додатковий код: чому «інверсія + 1» дає −N

Оскільки N = 37 додатне, беремо −37 у 8-бітному регістрі.

**Побудова:**

1. 37 = `00100101`
2. Інверсія бітів: `11011010`
3. Додаємо 1: `11011010 + 1 =` `11011011`

Отже, −37 = `11011011`. Перевірка: `11011011` = 219 = 256 − 37.

**Сума N і −N:**

```
  00100101   (37)
+ 11011011   (-37)
----------
1 00000000
```

Дев'ятий біт (одиниця переносу) відкидається, бо регістр 8-бітний, залишається `00000000` = 0.

**Пояснення словами:**

- Якщо число N та його інверсія складені по бітах, то в кожному розряді стоїть пара (0 і 1) або (1 і 0), тобто сума дорівнює 1 без переносів. Отже, N + інверсія(N) = `11111111` = 2⁸ − 1 (усі одиниці).
- Додавання одиниці до інверсії дає: N + (інверсія(N) + 1) = 2⁸ − 1 + 1 = **2⁸ = 256**.
- У 8-бітному регістрі значення 256 не вміщується: перенос у дев'ятий розряд відкидається, тобто арифметика виконується **за модулем 2⁸**. Тому 256 ≡ 0 (mod 256).

Отже, число `інверсія + 1` = 2⁸ − N задовольняє умову N + (2⁸ − N) ≡ 0 (mod 2⁸), а тому саме воно є −N у цьому регістрі. Це і є причина, чому додатковий код дозволяє замінити віднімання додаванням, без окремої схеми віднімання.
